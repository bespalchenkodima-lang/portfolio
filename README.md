# Dmitry Portfolio — V2

Портфолио Rust-разработчика с браузерной админкой, отзывами и списком серверов.

## Что есть

- Rust-проекты и галереи скриншотов;
- фильтры работ;
- услуга сборки и настройки Rust-сервера с нуля;
- управляемый из админки список серверов, с которыми вы работали;
- публичные отзывы без регистрации;
- оценка 0–5 звёзд;
- Turnstile CAPTCHA;
- ограничение: не чаще одного отзыва с одного подключения в час;
- удаление, скрытие и показ отзывов из админки;
- ручное добавление полученных извне отзывов (на публичной странице они честно помечаются «Добавлено владельцем»);
- Supabase RLS, привязанный к конкретному admin User ID;
- ограничения Storage по MIME и размеру файла;
- security headers для Cloudflare Pages.

## 1. Обязательно обновите SQL

Если первая версия уже была подключена, новый `supabase-setup.sql` является миграцией и создаст недостающие таблицы/политики.

Перед запуском:

1. Supabase -> Authentication -> Users.
2. Откройте свой аккаунт администратора.
3. Скопируйте `User ID`.
4. В `supabase-setup.sql` найдите:

```sql
00000000-0000-0000-0000-000000000000
```

и замените на свой User ID.

5. SQL Editor -> вставьте весь `supabase-setup.sql` -> Run.

**Это важно:** права на изменение сайта будут выданы только этому UID.

## 2. config.js

Оставьте ваши текущие:

```js
SUPABASE_URL: "...",
SUPABASE_ANON_KEY: "...",
```

Не вставляйте в браузер `service_role` key.

## 3. Настройка Cloudflare Turnstile

Создайте бесплатный Turnstile widget в Cloudflare.

Добавьте домены:

- ваш будущий `*.pages.dev`;
- ваш собственный домен, если будет;
- для локального теста Cloudflare предоставляет специальные test keys, либо временно тестируйте функцию после деплоя.

Site Key вставьте в `config.js`:

```js
TURNSTILE_SITE_KEY: "ВАШ_SITE_KEY"
```

Secret Key хранится только в Supabase Secrets.

## 4. Разверните Edge Function отзывов

Нужен Supabase CLI.

Из корня проекта:

```bash
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase functions deploy submit-review --no-verify-jwt
```

Затем задайте секреты:

```bash
supabase secrets set TURNSTILE_SECRET_KEY="ВАШ_SECRET_KEY"
supabase secrets set REVIEW_IP_SALT="ДЛИННАЯ_СЛУЧАЙНАЯ_СТРОКА"
supabase secrets set ALLOWED_ORIGINS="https://your-site.pages.dev,http://127.0.0.1:5500,http://localhost:5500"
```

`REVIEW_IP_SALT` придумайте длинный случайный (минимум 32 символа). IP в базе не хранится: хранится только SHA-256 хэш IP + salt для антиспама.

## 5. Важные настройки Authentication

В Supabase:

- отключите публичную регистрацию пользователей;
- используйте длинный уникальный пароль администратора;
- не создавайте дополнительные Auth Users без необходимости.

Даже если появится другой authenticated user, новые RLS-политики не дадут ему прав администратора.

## 6. Cloudflare Pages

Файл `_headers` уже содержит базовые security headers/CSP.

При загрузке проекта на Cloudflare Pages он будет применён автоматически для статического сайта.

## 7. Админка

Открывается вручную:

`/admin.html`

Ссылка на неё убрана из footer. Это не является основной защитой — основная защита находится в Supabase RLS.

В админке три раздела:

- Работы;
- Отзывы;
- Серверы.

## 8. Отзывы, добавленные вручную

Используйте их для реальных отзывов, которые вы получили, например, в Discord. Можно указать ник и источник.

Сайт автоматически показывает пометку «Добавлено владельцем», чтобы не выдавать созданный владельцем контент за независимый отзыв посетителя.
